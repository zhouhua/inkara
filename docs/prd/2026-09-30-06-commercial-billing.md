## 1. Summary

用尽「自备模型」路径，改为**平台提供模型、用户付费**。统一以**积分账本**计量；**单档会员**（月/季/年）+ **积分包**；日免以「当天有效积分」发放。移除 BYOK UI 与本机配额。

## 3. Background

### 现状

- 生产无用户 Key → 本机 IndexedDB 每天 2 次；清站点可重置。  
- BYOK 对话框 / 设定可填 Key、Endpoint、模型；`/api/probe` 测通。  
- `/api/ask` **无**用户鉴权、**无**服务端配额；Cloudflare Worker **无** D1/KV。  
- PRD 曾明确不做注册支付——本 PRD **正式推翻**该约束。

### 痛点

1. BYOK 把成本与复杂度甩给用户，转化差、体验碎。  
2. 本机配额无法防刷、无法跨设备、无法支撑真付费。  
3. 无身份则无法做订阅与退款责任边界。

---

## 4. Objective

**目标：** 用户感到「纸会一直愿意回答」的路径是办会员或补充次数，而不是去填 API Key。

### Key Results

| KR | 指标 | 目标 |
|----|------|------|
| KR1 | 生产路径无 BYOK | 设定与纸面无 Key/Endpoint/模型输入 |
| KR2 | 日免服务端强制 | 匿名/未付费每日恰好 2 次成功回答（可测） |
| KR3 | 付费入账可消费 | 支付成功后 ≤1min 可扣次 |
| KR4 | 扣减规则单测 | 软顶→购买积分→善意→拒绝 全覆盖 |
| KR5 | 纸面用尽动作 | 「续订 / 补充」明确文字按钮（非任意轻触） |

---

## 5. Market Segment(s)

| 细分 | Jobs to be done |
|------|-----------------|
| 尝鲜者 | 每天写一两句被接住，不强迫注册 |
| 习惯用户 | 一杯咖啡价办月会员，高峰日不被 2 次卡住 |
| 偶发超额 | 买小积分包，不办订阅 |

---

## 6. Value Proposition(s)

- **对用户：** 零配置模型；额度规则好懂（按次）。  
- **对产品：** 可预测收入；统一模型质量与风控。  
- **非价值：** 不卖「更强模型档位」、不做积分商城游戏化。

## 8. Scope

### In scope（分三期，见 plans）

1. **Auth + D1 账本核心**  
2. **ask 计费闸门 + 移除 BYOK + 用尽 UX**  
3. **官方微信/支付宝 checkout / webhook + 商品入账**

### Out of scope（V1）

- 微信登录（可 Phase 2）  
- 聚合支付平台、发票、海外支付、BYOK 企业后门  
- 多档模型、家庭计划  
- 微信 JSAPI / H5（V1 仅 Native 扫码 + 支付宝电脑网站）

---

## 9. UX 要点

- 用尽文案克制：「纸需要歇一歇」+ 文字按钮「续订或补充次数」。  
- 价目层：淡墨、少装饰；不要优惠倒计时、红点、胶囊促销条。  
- 账户页可静默显示余额；**纸面不做**「今日还剩 n 次」运营预告（延续 PRD-05 对余量预告的克制）。

---

## 10. Dependencies / Risks

| 风险 | 缓解 |
|------|------|
| ¥9.9 包 + 不限日耗被刷 | 服务端 IP/设备限流；异常人工封禁 |
| 匿名日免重生 | 接受小损耗；登录合并时校验 |
| 支付渠道可用性 | 抽象 `PaymentProvider`；订单幂等；双渠道独立配置 |
| Auth 选型延误 | V1 邮箱魔法链接；微信后置 |
