## 1. Summary

墨语系统提示将语气写死为「亲密、克制、略带好奇」。不同人需要略不同的纸——有人要更短更冷，有人要更暖。本 PRD 在设定中提供**极少选项的语气微调**，写入 system prompt，不做角色广场或人设市场。

## 3. Background

### 上下文

- 当前：`src/lib/prompts.ts` 的 `buildSystemPrompt(locale)` 固定语气。  
- 设定已有：语言、提交方式、纸张、辨认引用开关、BYOK。  
- 用户无法在不改编码的情况下改变「纸怎么说话」。

### 为什么现在做

主路径已稳定。语气是**低结构成本、高感知差异**的杠杆，比多本日记/账号更符合克制产品观。

---

## 4. Objective

**目标：** 用户用一次设定，就能让后续纸答明显更贴近自己想要的情绪距离，且选项不超过「扫一眼能选完」。

### Key Results

| KR | 指标 | 目标 |
|----|------|------|
| KR1 | 语气选项数量 | ≤ 3（不含「默认」则含默认共 3；见方案） |
| KR2 | 切换后下一轮问答生效 | 100% |
| KR3 | 盲测可区分度（人工） | 同一问题下，两种非默认语气与默认相比，评审能稳定分辨 ≥ 2/3 场 |
| KR4 | 回复仍短 | 继续约束 1–3 句；语气不得鼓励长文 |

---

## 5. Market Segment(s)

| 细分 | Jobs to be done |
|------|-----------------|
| 想被轻轻接住的人 | 更暖、少评判 |
| 想要干净回响的人 | 更短、更克制、少抒情 |
| 默认就好的人 | 不打开设定也完全不受影响 |

**约束：** 不做「猫娘 / 老师 / 律师」等人设；不做多角色切换器。

## 7. Solution

### 7.1 UX

设定页新增一行：

- 标签：语气 / Tone  
- 控件：`<select>`（与现有设定行一致）  
- 选项（MVP 锁定为以下三个，文案可微调）：

| 值 | 中文 | English | 语义 |
|----|------|---------|------|
| `balanced` | 平和（默认） | Balanced | 现行提示：亲密、克制、略好奇 |
| `warm` | 更暖 | Warmer | 更体贴、多一点安抚，仍短句、不鸡汤堆砌 |
| `spare` | 更省 | Spare | 更冷清、更短，少修辞，像批注 |

不在纸面放语气快捷入口（Non-Goal：纸面手势切语气）。

### 7.2 Key Features

| ID | 功能 | 说明 |
|----|------|------|
| F1 | `AppSettings.replyTone` | `'balanced' \| 'warm' \| 'spare'`，默认 `balanced` |
| F2 | Prompt 注入 | `buildSystemPrompt(locale, tone)` 增加 2–4 行语气补充，不推翻身份设定 |
| F3 | 设定 UI | SettingsPanel 一行选择 |
| F4 | 持久化 | IndexedDB settings 迁移兼容缺省字段 |
| F5 | 即时生效 | 下一轮 `/api/ask` 带上新语气即可；无需清记忆 |

### 7.3 User Stories & Acceptance Criteria

**Story A**  
As a 用户, I want 在设定里选「更暖」, so that 纸答更体贴。

- [ ] 选择后写入 settings  
- [ ] 随后一次 ask 的 system prompt 含 warm 约束  
- [ ] 仍输出合法 JSON 协议（intent / transcription / recallQuery / reply）

**Story B**  
As a 用户, I want 选「更省」, so that 回复更短更淡。

- [ ] spare 明确要求偏短、少形容词  
- [ ] 人工抽测 5 条，平均句数不高于 balanced

**Story C**  
As a 不关心语气的用户, I want 默认行为与现在一致, so that 升级无感。

- [ ] 缺省字段视为 `balanced`  
- [ ] balanced 文案与现行提示等价（允许小幅整理，不改人设）

### 7.4 AI System Requirements

| 项 | 要求 |
|----|------|
| 工具 | 现有 OpenAI 兼容视觉模型；无新工具 |
| 协议 | 输出 JSON schema 不变 |
| 评测 | 手工：固定 5 条中英书写样本 × 3 语气，检查是否破角色、是否过长、是否提 AI |
| 失败 | 模型忽略语气时不额外重试；属提示词迭代，不阻塞发版 |

### 7.5 Non-Goals

- 自定义自由文本人设  
- 超过 3 个预设、滑杆微调、多维（幽默×正式）矩阵  
- 按会话临时覆盖语气  
- 语气影响 recall 检索逻辑（仅影响 reply 文风与应和句）

### 7.6 Technology

- `src/lib/settings.ts`：类型与默认值  
- `src/lib/prompts.ts`：tone 段落  
- `src/app/api/ask/route.ts`：从 body 读 settings 已有 locale——确认 tone 随前端 settings 传入（今日 ask body 需核对并补充字段）  
- `SettingsPanel.tsx` + `i18n.ts`

### 7.7 Assumptions

- 用户要的是「情绪旋钮」，不是「另一个产品人格 IP」。  
- 1–3 句硬约束比华丽人设更重要，任何语气不得放松长度上限。
