# PRD：配额与自备 Key 体验（Quota & BYOK UX）

**产品：** 墨语 · inkara  
**文档编号：** PRD-05  
**日期：** 2026-09-24  
**状态：** Accepted（经 grilling 定稿）  
**设计原则对齐：** `.impeccable.md`（失败写在纸上；不做成运营弹窗；动作明确、不靠猜）

---

## 1. Summary

正式环境未配置用户自备 API Key 时，每日仅 2 次免费问答；用尽或 Key 有问题时，错误已写在纸上，但缺少明确下一步，且任意位置「轻触重试」与「去设定」语义混杂。本 PRD 改善：**用尽/缺 Key 的纸面引导**、**错误动作改为明确文字按钮**、**设定内 BYOK 校验与连接测试**——仍经本站 API 代发，不改计费模型，**不做**免费余量预告（KR1）。

## 3. Background

### 现状

| 项 | 实现 |
|----|------|
| 免费额度 | `FREE_DAILY_LIMIT = 2`，仅 `production` 且无用户 Key 时计数（`quota.ts`） |
| 存储 | IndexedDB 本机计数；清站点数据可重置 |
| 用尽文案 | `quotaExceeded` → 写在纸上 |
| 缺 Key | `missingKey` 等错误路径 |
| BYOK | 设定中 apiKey / baseUrl / model；随请求传服务端 |
| 失败交互 | 纸面轻触整区重试；无「去设定」热区；设定无连接测试 |

### 痛点

1. 用尽后要自己找设定；纸上提示未形成明确动作。  
2. 「轻触任意处重试」与配额类「再试也没用」冲突。  
3. Key / Endpoint 填错时反馈晦涩，设定里无法先测通。  

### Grill 结论摘要

- **砍掉 KR1**：不做设定页「今日免费 n/2」、不做答后「还剩 1 次」预告。  
- **纸面错误统一**为末行淡墨文字按钮；取消任意位置轻触重试。  
- **测试按钮进入 MVP**（原 F6 提前）。

---

## 4. Objective

**目标：** 用尽或 Key 有问题时，纸面一句话说明原因并给出**明确下一步**；设定里能校验格式并**试一下连接**——不靠余量预告制造运营感。

### Key Results

| KR | 指标 | 目标 |
|----|------|------|
| ~~KR1~~ | ~~免费余量预告~~ | **不做** |
| KR2 | 用尽 / 缺 Key 纸上文案 | 含设定指引 + 可点「去设定」 |
| KR3 | BYOK 可验证 | 本地校验 + 设定内「测试」最小 ping |
| KR4 | 不增加服务端防刷指纹 | 仍为本机配额 |

## 7. Solution

### 7.1 UX

**A. 设定页（无配额状态行）**

- **不**显示 `今日免费 used/limit`、**不**显示「开发模式不限次」余量区块。  
- BYOK 字段：apiKey / baseUrl / model。  
- **本地校验（点测试前 / 失焦可辅助）：** Key trim 为空不可测；baseUrl 若填须为合法 URL 形态；错误用设定内淡墨短句。  
- **「测试」按钮：** 调用服务端探测（见 7.5）；成功/失败短句写在设定面板内；不自动关设定、不上纸；**不计**免费次数、**不写**记忆。

**B. 纸面错误（MVP 必须，交互统一）**

- 保持「失败写在纸上」。  
- **取消**任意位置轻触重试。  
- 错误句下方一行淡墨文字按钮（无实心 pill、无 Toast）：  
  - 配额用尽 / 缺 Key → **「去设定」**（打开设定）  
  - 网络 / 上游等可恢复错误 → **「重试」**（触发原重试逻辑）  
- 同一错误一般只给一个主动作；不默认「重试 + 去设定」双按钮。

**C. 余量预告**

- **不做**（原 F5 / KR1）。

**D. 人话错误词典（纸面 + 设定测试共用映射）**

| 码 / 情况 | 人话方向（中英 i18n） |
|-----------|----------------------|
| `quota_exceeded` | 今日免费已用完，请在设定中填写自己的 API Key |
| `missing_api_key` | 未配置 API Key |
| `unauthorized`（如 401） | Key 无效或无权访问 |
| `network` | 网络不通，请稍后重试 |
| `upstream` | 服务暂时无法完成 |
| 其它 | 兜底：暂时无法完成 |

不把原始 stack / 供应商 HTML 写满纸面。

### 7.2 Key Features

| ID | 功能 | 阶段 |
|----|------|------|
| F1 | 设定页配额/BYOK 状态行 | **不做** |
| F2 | 用尽/缺 Key 纸文案 +「去设定」按钮 | MVP |
| F3 | 纸面错误动作分流（去设定 / 重试）；取消整区轻触重试 | MVP |
| F4 | 字段基本校验（非空、URL） | MVP |
| F5 | 剩 1 次余量提示 | **不做** |

| F7 | 服务端配额 / 账号 | 不做 |

### 7.3 User Stories & Acceptance Criteria

**Story A**  
As a 用尽免费次数的用户, I want 纸上明确「去设定」, so that 我能继续。

- [ ] 文案含设定指引  
- [ ] 「去设定」为可点淡墨文字按钮，打开设定  
- [ ] 配额错误不提供「重试」为主动作  
- [ ] 填入有效 Key 后下一次提交走 BYOK，不再拦配额  

**Story B**  
As a 遇到网络/上游失败的用户, I want 明确的「重试」按钮, so that 我不会误触整纸。

- [ ] 错误下方有「重试」文字按钮  
- [ ] 点纸面其它空白区域不再触发重试  
- [ ] 中英文齐全  

**Story C**  
As a 填写自备 Endpoint 的用户, I want 在设定里校验并测试连接, so that 少一次失败提交。

- [ ] Key 空 / 非法 URL 在设定内提示，不发探测  
- [ ] 「测试」走服务端最小 completion；结果在设定内短句  
- [ ] 不计免费次数、不写记忆  
- [ ] 401 等映射为人话，非原始 upstream HTML  

### 7.4 Non-Goals

- 免费余量预告（设定 n/2、纸面/dock「还剩 1 次」）  
- 提高或动态调整免费次数（产品策略变更需另批）  
- 服务端强制配额、设备指纹  
- 登录、订阅、支付  
- 多 Key 管理、团队空间  
- 优惠券式 Banner / 运营弹窗  

### 7.5 Technology

- `src/lib/quota.ts`、`settings.ts`、`SettingsPanel.tsx`  
- `InkPage.tsx`：错误展示改为动作按钮；移除/停用整区轻触重试  
- 新 `POST /api/probe`（或 `/api/ask` + `mode: "probe"`）：同一 Key/baseUrl/model，最小 `chat/completions`；不计配额、不写记忆  
- `src/app/api/ask/route.ts`：错误码稳定映射便于前端人话  
- i18n 文案更新  
- README 与设定说明保持一致（诚实说明本机清数据可重置计数）

### 7.6 Security & Privacy

- Key 仍仅存本机 IndexedDB；经服务端转发时不写日志明文 Key。  
- 「测试」不得把 Key 发往第三方分析；不在客户端直连用户 baseUrl（避免 CORS 与 Key 暴露面扩大）。

### 7.7 Assumptions

- 2 次免费策略短期不变。  
- 用户可接受本机清数据即重置计数（文档诚实说明即可）。  
- 用户接受「用尽才告知」——不做事前余量 UI。
