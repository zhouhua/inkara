# PRD：旧页沉淀与回顾（History & Recall）

**产品：** 墨语 · inkara  
**文档编号：** PRD-03  
**日期：** 2026-09-24  
**状态：** Draft  
**设计原则对齐：** `.impeccable.md`（控件按需；面板保持淡墨，不做仪表盘）

---

## 1. Summary

墨语已能把问答存入本地记忆（最多 40 页），支持日历筛选与墨迹召回（「找××那页」）。但回顾面板以只读列表为主，**难以检索、难以把旧页唤回纸面继续写**。本 PRD 强化「沉淀」：让旧页更好找、能回到纸上、与墨迹召回形成闭环。

## 3. Background

### 现状能力

| 能力 | 状态 |
|------|------|
| IndexedDB 记忆，上限 40，上下文约 8 页 | 已有（`src/lib/memory.ts`） |
| 回顾面板：按日筛选、删除单页、清空 | 已有（`HistoryPanel` + `HistoryCalendar`） |
| 墨迹召回 intent=recall | 已有（模型 + 前端匹配） |
| 从列表点开某页并淡墨铺到纸面 | **缺失或弱** |
| 关键词搜索旧页 | **缺失** |
| 从旧页「接着写」 | **缺失** |

### 为什么现在做

有记忆却不好用，会浪费已产生的内容资产；且召回依赖模型理解，失败时用户没有可靠的手动路径。

---

## 4. Objective

**目标：** 用户能在 10 秒内找到某次写下的内容，并能选择「只是看看」或「铺回纸面」。

### Key Results

| KR | 指标 | 目标 |
|----|------|------|
| KR1 | 回顾面板支持关键词过滤 | transcription + reply 子串匹配 |
| KR2 | 列表项可「铺回纸面」 | 进入 recalling 视觉或等价淡墨重现 |
| KR3 | 墨迹召回失败时 | 纸上提示可打开回顾（文案指引，不强制跳转） |
| KR4 | 面板视觉 | 不引入卡片堆、统计图表、侧边导航树 |

---

## 5. Market Segment(s)

| 细分 | Jobs to be done |
|------|-----------------|
| 隔天回来的人 | 「我昨晚写过什么？」 |
| 用句子找旧页的人 | 「找失眠那页」——模型或搜索 |
| 想续写情绪的人 | 看到旧答后在同一语境再写一句 |

**约束：** 数据仍仅本机；不做云同步（见总规划候选 7，非本 PRD）。

| 维度 | 内容 |

| 避免 | 只能靠模型猜对才能召回 |
| 差异 | 仍是日记式回顾，不是 Notion 数据库 |

## 7. Solution

### 7.1 UX / 流程

**回顾面板增强**

1. 标题下增加一行极简搜索框（placeholder：「搜索写下的字或纸答」）。  
2. 过滤 = 日历日筛选 ∩ 关键词（忽略大小写；中文直接子串）。  
3. 每条 entry 增加操作：  
   - **铺回纸面**（主操作）：关闭面板 → 纸面进入回顾态，展示该页 transcription/reply 的淡墨重现（复用现有 recall 展示路径）。  
   - 保留 **遗忘**。  
4. 空搜索 + 空日历 = 现有全部列表。

**与墨迹召回关系**

- 墨迹召回逻辑保留；匹配算法可小幅改进（本 PRD MVP 可不改算法，只补手动路径）。  
- `recallMiss` 文案增加一句：可打开「旧页」自行查找（不自动打开面板，避免打断）。

**「接着写」（MVP 范围）**

- MVP：**铺回纸面为只读回顾**；轻触纸面回今天（保持现行为）。  
- v1.1：回顾态下允许书写并提交，提交时把该旧页上下文注入 memory（需另开任务，见 Release）。

### 7.2 Key Features

| ID | 功能 | MVP |
|----|------|-----|
| F1 | 回顾关键词搜索 | Yes |
| F2 | 列表 → 铺回纸面 | Yes |
| F3 | recallMiss 文案引导 | Yes |
| F4 | 搜索无结果空态 | Yes |
| F5 | 回顾态续写 | No（v1.1） |
| F6 | 导出多页 / 分享链接 | No |
| F7 | 提高 40 页上限或分页云端 | No |

### 7.3 User Stories & Acceptance Criteria

**Story A**  
As a 用户, I want 在旧页里搜「失眠」, so that 立刻看到相关条目。

- [ ] 输入防抖 ≤ 300ms 或即时过滤均可  
- [ ] 匹配 transcription 或 reply  
- [ ] 与日历筛选同时生效  
- [ ] 无匹配时显示明确空态（中英文）

**Story B**  
As a 用户, I want 点某条「铺回纸面」, so that 在纸上重读那次对话。

- [ ] 关闭 HistoryPanel  
- [ ] 纸面展示该页内容（视觉上可辨为回顾，非新答动画强行播放一遍长文——优先淡墨静置或沿用现有 recall 动画）  
- [ ] 现有「轻触回到今天」仍可用  
- [ ] 不错误写入一条新 memory

**Story C**  
As a 用户, I want 墨迹召回找不到时仍有退路, so that 不卡死。

- [ ] miss 文案提及旧页入口  
- [ ] 不自动弹面板

### 7.4 Non-Goals

- 多本日记 / 笔记本分册（候选 6）  
- 全文语义向量搜索  
- 服务端同步、多设备  
- 把回顾做成双栏笔记编辑器

### 7.5 Technology

- `HistoryPanel.tsx`：搜索 state、操作按钮  
- `InkPage.tsx`：暴露 `recallPageById(id)` 或传入 `MemoryPage` 的展示函数（与现有 recall 路径合并）  
- `memory.ts`：`getPageById`（若尚无）  
- `i18n.ts`：新文案  
- 样式：沿用 `.history-*`，搜索框用现有 ink 表单风格

### 7.6 Assumptions

- 40 页内子串搜索足够；无需索引库。  
- 「铺回纸面」是用户对沉淀的最大获得感，高于精美日历。
